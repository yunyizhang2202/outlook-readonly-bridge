# 恢复来源与验证边界

整理日期：2026-10-22（Europe/London）。

## 来源

恢复自维护方此前私有协作项目中 `bridge/outlook-readonly` 的完整源码目录；不复制私有任务板、聊天、组织信息、设备目录、任何实际隧道或密钥。其 setup 已含 2026-10-11 Windows 正斜杠路径修复。

历史 2026-10-10/11 记录分别报告：经典 Outlook COM、本机 Python 检查、8 个核心测试和 MCP 协议测试通过；当时部分记录仍停在隧道/远程阶段。后续 2026-10-20/21 对话记录确认自制连接器能远程读取学校邮箱与另一个个人邮箱。这些是历史证据，不是本仓库在朋友电脑上的实测。最初成功对话的准确标题/链接尚未恢复。

## 本次改变

- 核心默认白名单改为空；由不入库的 `config.local.json` 显式授权精确地址/域名，支持其他学校和个人账户。
- 保留五个只读工具、分页/大小上限、STA 子进程 COM、本机 DPAPI 存储和官方 Tunnel 路径。
- 新增不会输出邮箱/正文/进程命令行的基础诊断和配置测试。
- 新增权限分流、搭建验收与双方 GPT 交接格式。
- 原始历史依赖快照保留作参考，正式安装沿用固定 MCP v1；不把新版本 SDK API 与历史代码混用。

## 本次验证

详见 `VALIDATION.md` 的实际运行结果。Linux 制作环境不能测试真实 Windows COM、DPAPI、UAC、朋友的 Outlook、朋友的 Tunnel 或远端 ChatGPT；这些必须由接手 GPT 在目标环境逐项验收。
